# hud-editor (визуальный редактор HudLayout.txt)

Parent: [[Index]] | Domain: [[Tooling/Tools]] | Формат: [[Client/HUD-layout]]

## Назначение
Веб-редактор `scripts/HudLayout.txt` — блоков `HudLayout`, `HudDecorations` и опциональной темы
`ScoreboardStyle`. Без сборки и
npm-зависимостей: три статических файла, открываемых любым статическим сервером.

## Запуск
`start-hud-editor.cmd` в корне репозитория (поднимает `npx http-server tools/hud-editor -p 8080`
и открывает браузер). Обязательно по `http://`, не `file://` — на схеме `file` браузеры блокируют
File System Access API. Нужен Chrome/Edge: чтение/запись файла идут через
`window.showOpenFilePicker` / `showSaveFilePicker`, в других браузерах кнопки «Открыть/Сохранить»
покажут предупреждение.

## Файлы
| Файл | Содержимое |
|------|-----------|
| `tools/hud-editor/index.html` | Только разметка: тулбары, боковая панель, `#stageArea` (линейки + холст) |
| `tools/hud-editor/editor.css` | Стили, включая подсветку выделения (`.selected`), направляющие, рамку выделения |
| `tools/hud-editor/editor.js` | Вся логика: модель, парсер/сериализатор, drag, выделение, группы, история |

## Модель данных

`state` — то, что попадает в файл: `resW/resH`, `elements`, `decorations`, `scoreboardStyle`, `groups`.
`view` — сессионные настройки (зум, сетка, привязка, линейки, подложка), в файл не пишутся.
Флаги `locked`/`hidden` живут на самих элементах, но сериализатор их не выводит — тоже сессионные.

### Флаг `override` («переопределять»)

У каждого элемента есть флаг `override`. Снят → запись **не пишется** в файл, и игра рисует элемент
по своему дефолту. В самом файле флаг не хранится: **наличие записи и есть флаг**, формат не менялся.

Это не косметика. Для пяти элементов дефолт вычисляется в рантайме и триплетом `x/y/anchor` не
выражается (`WeaponMenu`, `Scenario`, `ProgressBar`, `SayText`, `Train` — см.
[[Client/HUD-layout]]); запись для них заменила бы живой дефолт мёртвой константой. Раньше
`serializeHudLayout` писал все id безусловно, поэтому такой элемент всегда получал
`m_bLayoutOverridden = true`.

Побочный эффект, принятый осознанно: загрузка стала честным round-trip. Id, удалённый из файла
вручную, остаётся удалённым, а не восстанавливается из `DEFAULT_ELEMENTS` при следующем
сохранении — эти значения теперь только заполняют поля ввода.

`DEFAULT_OVERRIDDEN` — набор id, которые пишет новый конфиг (15 из 20): элемент попадает туда,
только если его игровой дефолт — константа, и запись ничего не меняет.

Для каждого из 20 HUD-элементов панель показывает `x`, `y`, `anchor` и `scale`. Scoreboard получает
реалистичное 5×5 preview со строками, аватарами, заголовками и цветами темы. Отдельная панель
редактирует geometry, RGBA и `dead_alpha`, умеет сбрасывать CS2 preset и участвует в undo/redo.
Scale имеет
минимум `0.1`, сохраняется как пятый токен записи и применяется игровым кодом к этому блоку;
для текста рантайм использует scaled-рендеринг Xash Mobile API, когда он доступен. Ограничение
`override` относится к записи координат/якоря и вычисляемым игровым дефолтам, а не к списку
поддерживаемых масштабируемых элементов.

Выделение и группы адресуются **стабильными ключами**, а не индексами массива:
`el:<Id>` для HUD-элементов, `dec:<uid>` для декораций (`uid` выдаётся в рантайме при создании и
при парсинге). Поэтому удаление или перестановка декорации не может тихо перенаправить выделение
или члена группы на чужой бокс. При сохранении `dec:<uid>` переводится в `dec:<индекс в файле>`
и обратно при загрузке.

### Тема Scoreboard

Переключатель `theme override` управляет наличием блока `ScoreboardStyle` в сохранённом файле.
Geometry-поля и девять RGBA-цветов редактируются в отдельной панели; reset возвращает встроенный
CS2 preset. Изменения темы входят в обычные snapshots, поэтому Ctrl+Z/Ctrl+Shift+Z, New, Open и
Save не теряют их. Если исходный файл не содержал тему, Open → Save не добавляет её сам.

## Ключевые функции
| Функция | Описание |
|---------|----------|
| `resolveAnchoredPos` / `inverseAnchoredPos` | Зеркало `ResolveAnchoredPos()` из `hud_layout.cpp`: две независимые оси, полная сетка 3×3 якорей |
| `normalizeAnchor(name)` | Приводит алиасы (`center_top`, `topright`, …) к каноническому имени |
| `itemOrigin(key)` / `setItemOrigin(key, x, y)` | Точка привязки, которую резолвит игра; запись идёт через inverse-anchor + округление |
| `itemRect(key)` | Нарисованный footprint. Отличается от origin у right-aligned элементов, `StatusBar`, `TeamBar` и `XPBar` — поэтому перемещение идёт через origin, а привязка и выравнивание через rect |
| `getElementPreview(id, element)` | Габариты HUD-блока и его runtime-origin для превью; `TeamBar`, `XPBar` и `Scoreboard` центрируются по origin, scoreboard fit уменьшается на маленьком холсте |
| `beginDrag(startEv, onMove, onEnd)` | Считает **float**-дельту от точки mousedown; вызывающий применяет `round(start + delta)` |
| `computeSnap(keys, startRects, dx, dy)` | Одно смещение на всё выделение: края/центр холста, рёбра и центры соседей, сетка. Возвращает направляющие |
| `startMoveDrag(ev)` | Двигает всё выделение; каждый член проходит свой anchor round-trip |
| `alignSelection(mode)` / `distributeSelection(axis)` | Выравнивание по bounding box выделения / равные зазоры |
| `groupsToComment()` / `groupsFromComment(text, decorations)` | Сериализация групп в `// EditorGroups:` и разбор регуляркой **до** `tokenize()` |
| `pushHistory()` / `undo()` / `redo()` | Снапшоты `state` в JSON, лимит 100, одинаковые подряд отбрасываются |

### Почему drag устроен именно так

Первая версия копила `ev.movementX / scaleK` и округляла на **каждом** mousemove. На холсте
2560×1440, вписанном в окно (`scaleK ≈ 0.35`), один пиксель мыши = ~3 игровых пикселя, а любая
дробная часть, округляющаяся в ноль, терялась безвозвратно — точное позиционирование было
невозможно, отсюда и ручное «доведение» координат в полях. Сейчас дельта копится как float от
точки нажатия, а `round(start + delta)` применяется раз в кадр. Побочный эффект: раз стартовые
координаты целые, а дельта одна на всех, относительные расстояния внутри группы сохраняются
точно.

### Почему выделение — не класс на DOM-узле

`renderStage()` делает `stage.innerHTML = ""` и пересобирает узлы, в том числе на каждом
mousemove. Любой класс, повешенный на узел, был бы стёрт следующим кадром. Выделение живёт в
`Set` ключей, а `renderStage()` / `renderElementsList()` / `renderDecorationsList()` выводят
подсветку из него — отсюда же бесплатная синхронизация «холст ↔ боковая панель» в обе стороны.

## Управление
| Действие | Как |
|----------|-----|
| Выделить | Клик по элементу на холсте или по строке в панели |
| Добавить/убрать из выделения | Ctrl/Shift + клик |
| Рамкой | Протяжка по пустому месту холста |
| Выделить всё / снять | Ctrl+A / Esc |
| Группа | Ctrl+G, разгруппировать Ctrl+Shift+G. Клик по члену берёт всю группу, Alt+клик — только один элемент |
| Сдвиг на 1 / 10 px | Стрелки / Shift+стрелки |
| Без привязки | Alt во время перетаскивания |
| Отмена / повтор | Ctrl+Z / Ctrl+Shift+Z (или Ctrl+Y) |
| Дублировать декорацию | Ctrl+D |
| Удалить декорацию | Del |

Порядок отрисовки декораций = порядок в файле (отдельного z-поля в формате нет), поэтому
кнопки `↑`/`↓` в строке декорации — единственный способ управлять перекрытием.

Подложка (скриншот игры) и блокировка/скрытие элементов — сессионные: подложка нужна, чтобы
выравнивать HUD по реальному кадру, блокировка — чтобы полноэкранный `Shade` не перехватывал
все клики.

## Ограничения
- Превью содержимого элементов иллюстративное: живых значений и спрайтов оружия в браузере нет.
- Масштаб превью применяется ко всем HUD-элементам, но для текстовых и стековых блоков габарит
  остаётся ориентировочным: реальное содержимое и число активных строк/иконок меняются в игре.
- Превью элементов, растущих вверх от origin (`StatusIcons`, `AmmoHistory`, `XPBar`), задано через
  `originY: -height`; у XPBar origin — нижний центр полосы, над ним располагаются уровень и popup.
- Превью стековых элементов (`StatusIcons`, `AmmoHistory`, `WeaponMenu`, `SayText`, `TeamBar`) —
  представительный случай с фиксированным числом записей; реальный блок растёт вместе с их числом.
  `StatusIcons` и `AmmoHistory` растут **вверх** от точки привязки, поэтому их превью задано через
  `originY: -height` и лежит выше origin.
- Холст надо выставлять в фактическое разрешение игры (для текущего runtime есть пресет
  2560×1440), иначе якоря и декорации визуально смещены.
- Группы, разрешение превью и прочие метаданные редактора хранятся в `//`-комментариях — игра их
  игнорирует, но сторонний редактор файла может их потерять.
