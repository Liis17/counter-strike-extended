# Архитектура

Parent: [[Index]]

## Tech Stack

| Слой | Технология |
|------|-----------|
| Движок | Xash3D FWGS (C, Waf build system) — форк Half-Life Engine |
| Клиент игры | CS16Client (C/C++, CMake) — реверс-инженеренный клиент CS 1.6 |
| Игровой сервер | ReGameDLL_CS (C++, часть `cs16-client`, `BUILD_SERVER=ON`) + YaPB proxy |
| Рендер | OpenGL / GLESv1 / GLESv2 / Software (через движок) |
| Платформы | Windows, Linux, BSD, Android, macOS, PS Vita |
| Инструменты | PowerShell и Python 3 (install-скрипты, генератор палитров моделей) |
| Прогрессия | Клиентский локальный профиль в `cs16-client/cl_dll` + KV-конфиг в `src/cse/` |

## Состав репозитория

```
counter-strike-extended/
├── src/
│   ├── xash3d-fwgs/    ← submodule, движок (github.com/Liis17/xash3d-fwgs)
│   └── cs16-client/    ← submodule, клиент (github.com/Liis17/cs16-client), включая CSE client fork changes
│       ├── 3rdparty/ReGameDLL_CS/ ← серверная GameDLL при BUILD_SERVER
│       └── 3rdparty/yapb/         ← proxy/боты для серверного запуска
│   └── cse/
│       └── cstrike/
│           ├── server.cfg          ← правила dedicated-матча
│           ├── mapcycle.txt        ← пул карт для случайной ротации
│           └── scripts/            ← игровые KV-конфиги
├── tools/
│   ├── screenshot_window.ps1
│   ├── mdl_recolor.py
│   ├── install_progression.ps1
│   └── install_skins.ps1
└── runtime/            ← gitignored: скомпилированный движок + лицензионные Steam-ассеты (valve/, cstrike/)
```

Сам репозиторий — тонкая обвязка (`.gitmodules`, `.gitignore`, `build-cse.cmd`) вокруг движка и submodule
`cs16-client`, внутри которого находятся клиент, серверная ReGameDLL_CS и YaPB. Корневой `build-cse.cmd`
оркестрирует Waf/CMake, развёртывание и install-скрипты; сборка самого движка и клиента идёт по их
инструкциям (Waf для движка, CMake для клиента и серверной DLL).

## Сквозной поток: сборка → запуск

1. Движок (`src/xash3d-fwgs`) собирается через Waf → бинарники движка (`xash3d.exe`, `xash.dll`, рендереры `ref_gl.dll`/`ref_soft.dll`, `filesystem_stdio.dll`, `menu.dll` и т.д.)
2. Клиент и сервер (`src/cs16-client`) собираются через CMake → `cl_dll`, ReGameDLL/`mp.dll` и YaPB, устанавливаются в директорию движка
3. Легальные ассеты Half-Life (`valve/`) и Counter-Strike (`cstrike/`) копируются владельцем лицензии в `runtime/` — сам репозиторий их не хранит и не распространяет (см. `.gitignore`, `CAUTION` в README движка)
4. Install-скрипты разносят проектные конфиги из `src/cse/` в `runtime/`; `CseProgression.txt` читается
   клиентской DLL при подключении, `install_server_config.ps1` устанавливает правила dedicated-матча,
   а `install_skins.ps1` генерирует палитровые производные моделей из локальных лицензированных
   исходников.
5. `runtime/xash3d.exe` запускает движок, который грузит клиентские DLL и ассеты

При запуске dedicated-сервера `tools/prepare_server_maps.ps1` перемешивает проектный map pool,
выбирает стартовую карту и записывает случайный порядок в runtime `mapcycle.txt`. ReGameDLL
использует `mp_winlimit 6` и меняет карту после шести побед одной команды; лимит времени и общий
лимит раундов отключены.

Для карт штатные действия выполняются серверной ReGameDLL из entity lump: `func_button`,
триггеры и `game_*` передают цели по `target`/`targetname`. Новый серверный classname или
новое сетевое событие затрагивает ReGameDLL и, для HUD, `cl_dll`; подробности — [[CSE/map-actions]].

`runtime/` — не источник правды, это выходная директория сборки + скопированные вручную лицензионные ассеты.
Полностью в `.gitignore`.

## Как добавить новый компонент

Новый submodule/инструмент → своя заметка в `{Domain}/`, ссылка в [[Index]]. Для апстрим submodule фиксируем
только: назначение, точку сборки, точку интеграции с остальным репо — без копирования апстрим-README целиком.
