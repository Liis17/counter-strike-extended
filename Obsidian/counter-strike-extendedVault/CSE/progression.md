# Система прогрессии игрока

Parent: [[Index]]
Связанные: [[Архитектура]], [[Tooling/Tools]], [[Client/cs16-client]]

## Статус

Клиентский этап 1 реализован: локальный профиль, XP, уровни и статистика.
Серверный флаг бота и отображение скинов для других игроков ещё не реализованы.

## Где живёт код

| Компонент | Путь | Назначение |
|-----------|------|------------|
| Профиль и события | `src/cs16-client/cl_dll/cse_profile.{h,cpp}` | Загрузка/сохранение профиля, начисление XP, команды и обработчики игровых событий |
| Конфиг прогрессии | `src/cs16-client/cl_dll/cse_progression.cpp` | Разбор `scripts/CseProgression.txt`, значения XP и пороги уровней |
| Конфиг проекта | `src/cse/cstrike/scripts/CseProgression.txt` | Источник правды для развёртывания в runtime |
| Установка | `tools/install_progression.ps1` | Идемпотентное копирование конфига в `runtime/cstrike/scripts/` |

Клиентская часть находится в форке `src/cs16-client`; проектный KV-конфиг остаётся в `src/cse/`.

## Поток данных

1. После `CHudScoreboard::Init()` `CSE_Init()` определяет `m_nSteamID` локального слота и загружает
   `cse_profile_<steamid64>.txt`; при нулевом SteamID используется `cse_profile_local.txt`. Если SteamID
   приходит позднее через userinfo, профиль перепривязывается на первом следующем событии/кадре.
2. `MsgFunc_DeathMsg` передаёт убийцу, жертву и headshot в `CSE_OnDeathMsg()`.
3. `MsgFunc_TeamScore` передаёт имя команды и счёт в `CSE_OnTeamScore()`.
4. `CHud::Redraw()` передаёт состояние intermission в `CSE_OnIntermission()`; фронт `0 → 1` начисляет
   результат матча только при участии хотя бы в одном раунде на этой карте.
5. Профиль сохраняется после учтённого раунда, на фронте intermission и в `CHud::Shutdown()`.

### Защита от ложных раундов

Для каждой команды первый `TeamScore` только запоминается. XP за раунд начисляется исключительно при
`delta == +1`; полный sync при входе и сброс счёта не создают события. При этом последний счёт обновляется
на каждом сообщении. Участие хранится во временном `m_iRoundsThisMap`, а команда последнего учтённого
раунда — отдельно; поэтому переход в спектаторы перед концом матча не стирает уже подтверждённое участие.
Оба значения не попадают в файл профиля.

## Форматы

Конфиг содержит блоки `CseXP`, `CseLevels` и зарезервированный для следующего этапа `CseSkins`.
Парсер использует `COM_LoadFile`/`COM_ParseFile`; записи блоков XP и уровней имеют фиксированную арность.
При отсутствии конфига применяются встроенные значения по умолчанию.

Профиль хранит только счётчики и XP; уровень вычисляется из XP и порогов, отдельного списка `unlocked` нет:

```text
"CseProfile"
{
    "xp"           "12345"
    "kills"        "210"
    "headshots"    "44"
    "deaths"       "180"
    "round_wins"   "60"
    "round_losses" "52"
    "match_wins"   "7"
    "match_losses" "4"
    "equipped"     "ak47:gold"
}
```

## Методы

| Метод | Назначение |
|-------|-----------|
| `CSE_Init()` | Регистрирует команды, загружает конфиг и профиль |
| `CSE_InitHUDData()` | Сбрасывает только счётчики текущей карты на `InitHUD` |
| `CSE_LoadProfile()` / `CSE_SaveProfile()` | Читает/пишет профиль текущего SteamID |
| `CSE_AwardXP()` | Начисляет XP и обновляет соответствующий счётчик |
| `CSE_LevelForXP()` | Вычисляет уровень без хранения второго источника правды |
| `CSE_OnDeathMsg()` | Учитывает убийства, headshot и собственную смерть |
| `CSE_OnTeamScore()` | Учитывает победу/поражение раунда по дельте счёта |
| `CSE_OnIntermission()` | Учитывает итог матча один раз на фронте intermission |
| `cse_stats` | Печатает XP, уровень и статистику в консоль |
| `cse_profile_reload` | Повторно читает конфиг и профиль без перезапуска клиента |

## Следующие этапы

Бот-множитель уже читается из конфига и подготовлен в API `CSE_AwardXP()`, но серверный флаг бота будет
подключён отдельным этапом через ReGameDLL. Таблица `CseSkins` пока пропускается парсером и будет
использована этапом выбора/подмены моделей.
