# Система прогрессии игрока

Parent: [[Index]]

## Статус

Клиентский этап 1 реализован: локальный профиль, XP, уровни и статистика.
Этап 2 реализован: множитель за ботов читается на клиенте из userinfo-ключа `*bot`, серверная часть не понадобилась.
Этап 3 реализован: палитровые перекрасы view/world моделей генерируются из лицензированных runtime-ассетов.
Этап 4a реализован: выбор скина хранится в профиле, публикуется в `cse_skins` и меняет только собственный viewmodel.
Этап 4b реализован: экран персонализации показывает рецепты и уровень, экипирует доступные скины и хранит
предпочитаемого оперативника отдельно для T/CT ([[CSE/personalization]]).
Этап 5 реализован: `CHudXPBar` показывает уровень, прогресс до следующего уровня и временный popup прироста XP.
Серверное отображение для других игроков ещё не реализовано.

## Поток данных

1. После `CHudScoreboard::Init()` `CSE_Init()` определяет `m_nSteamID` локального слота и загружает
   `cse_profile_<steamid64>.txt`; при нулевом SteamID используется `cse_profile_local.txt`. Если SteamID
   приходит позднее через userinfo, профиль перепривязывается на первом следующем событии/кадре.
   Локальные скины и T/CT-оперативники переносятся в SteamID-профиль, только если игрок менял их
   в текущем запуске до подключения; иначе загружается сохранённая персонализация SteamID.
2. `MsgFunc_DeathMsg` передаёт убийцу, жертву и headshot в `CSE_OnDeathMsg()`; жертва проверяется на
   бота через userinfo-ключ `*bot`, и флаг уходит в оба начисления — за убийство и за headshot.
3. `MsgFunc_TeamScore` передаёт имя команды и счёт в `CSE_OnTeamScore()`.
4. `CHud::Redraw()` передаёт состояние intermission в `CSE_OnIntermission()`; фронт `0 → 1` начисляет
   результат матча только при участии хотя бы в одном раунде на этой карте.
5. Профиль сохраняется после учтённого раунда, на фронте intermission и в `CHud::Shutdown()`.
6. `cse_skin <weapon> <skin>` проверяет рецепт и вычисленный уровень, обновляет `equipped` в профиле,
   затем `CSE_SkinsSyncCvar()` публикует компактное значение через `gEngfuncs.Cvar_Set("cse_skins", ...)`.
7. Профиль публикует вычисленный уровень и T/CT-оперативников через `cse_level`, `cse_operator_t` и
   `cse_operator_ct`; `cse_operator <t|ct> <model>` валидирует и сохраняет новый выбор.
8. `CSE_SkinViewModel()` сопоставляет только `models/v_ak47.mdl` и `models/v_awp.mdl`; при отсутствующем
   производном файле `DefaultDeploy()` повторяет загрузку stock-модели.
9. `CHudXPBar::Draw()` берёт XP из профиля, вычисляет уровень и порог следующего уровня через
   `cse_progression.cpp`; изменение XP между кадрами запускает popup только для положительного прироста.

### Защита от ложных раундов

Для каждой команды первый `TeamScore` только запоминается. XP за раунд начисляется исключительно при
`delta == +1`; полный sync при входе и сброс счёта не создают события. При этом последний счёт обновляется
на каждом сообщении. Участие хранится во временном `m_iRoundsThisMap`, а команда последнего учтённого
раунда — отдельно; поэтому переход в спектаторы перед концом матча не стирает уже подтверждённое участие.
Оба значения не попадают в файл профиля.

## Форматы

Конфиг содержит блоки `CseXP` и `CseSkins`; неизвестные блоки парсер пропускает целиком.
Парсер использует `COM_LoadFile`/`COM_ParseFile`; записи блоков имеют фиксированную арность.
При отсутствии конфига применяются встроенные значения по умолчанию.

Лестница уровней — линейная и без потолка: `level = 1 + xp / xp_per_level`, где `xp_per_level`
задаётся в блоке `CseXP` (по умолчанию `10000`, значение меньше `1` подтягивается до `1`). Потолок
один — на самом XP: `CSE_AwardXP()` насыщается на `INT_MAX` вместо переполнения, что даёт
максимальный уровень `1 + INT_MAX / xp_per_level`. Таблица порогов `CseLevels`
~~убрана~~ (удалена: 2026-08-11) — блок в старых конфигах просто игнорируется.

Рецепты перекрасов — отдельный блок для Python-генератора. Пути считаются относительно
`runtime/cstrike`, преобразование задаётся как `hue=<градусы>;tint=R,G,B`:

```text
"CseSkinRecipes"
{
    "models/v_ak47.mdl" "hue=0;tint=1.15,0.28,0.28" "models/cse/v_ak47_red.mdl"
}
```

Встроенные текстуры остаются в выходном `.mdl`. Если исходный заголовок содержит `numtextures 0`,
рядом с выходом создаётся также `<output>T.mdl`; геометрия основного файла копируется без изменений.
Производные модели не коммитятся: они зависят от локальных лицензированных ассетов из `runtime/`.

Профиль хранит счётчики, XP, выбранные скины и оперативников; уровень вычисляется из XP и шага
`xp_per_level`, отдельного списка `unlocked` нет:

```text
"CseProfile"
{
    "xp"           "12345"
    "kills"        "210"
    "headshots"    "44"
    "deaths"       "180"
    "round_wins"   "60"
    "round_losses" "52"
    "match_wins"   "7"
    "match_losses" "4"
    "equipped"     "ak47:gold;awp:default"
    "operator_t"    "guerilla"
    "operator_ct"   "sas"
}
```

## Методы

| Метод | Назначение |
|-------|-----------|
| `CSE_Init()` | Регистрирует команды, загружает конфиг и профиль |
| `CSE_InitHUDData()` | Сбрасывает только счётчики текущей карты на `InitHUD` |
| `CSE_LoadProfile()` / `CSE_SaveProfile()` | Читает/пишет профиль текущего SteamID |
| `CSE_SyncProfileCvars()` | Публикует для `menu.dll` уровень, скины и выбранных оперативников после загрузки профиля (внутренняя) |
| `CSE_RefreshProfileIdentity()` | При получении SteamID загружает его профиль и переносит локальную персонализацию, только если её меняли до подключения |
| `CSE_IsOperatorForTeam()` / `CSE_ValidateOperators()` | Проверяет профиль по общему каталогу оперативников и восстанавливает штатные значения (внутренние) |
| `CSE_CommandOperator()` | Валидирует аргументы `cse_operator`, сохраняет модель и обновляет cvar (внутренняя) |
| `CSE_AwardXP()` | Начисляет XP с насыщением на `INT_MAX`, применяет бот-множитель и обновляет счётчик |
| `CSE_LevelForXP()` | Вычисляет уровень как `1 + xp / xp_per_level`, без хранения второго источника правды |
| `CSE_XPForLevel()` / `CSE_XPForNextLevel()` | Возвращают границы текущего и следующего уровня для HUD; следующий даёт `-1`, когда не влезает в `int` |
| `CSE_PlayerIsBot()` | Читает userinfo-ключ `*bot` для индекса игрока (внутренняя, `cse_profile.cpp`) |
| `CSE_OnDeathMsg()` | Учитывает убийства, headshot и собственную смерть; за ботов платит по множителю |
| `CSE_OnTeamScore()` | Учитывает победу/поражение раунда по дельте счёта |
| `CSE_OnIntermission()` | Учитывает итог матча один раз на фронте intermission |
| `CSE_SkinsInit()` / `CSE_SkinsSyncCvar()` | Регистрирует команды/cvar и публикует выбор из профиля в userinfo |
| `CSE_SkinViewModel()` | Возвращает разрешённый производный viewmodel или stock-путь |
| `cse_stats` | Печатает XP, уровень и статистику в консоль |
| `cse_profile_reload` | Повторно читает конфиг и профиль без перезапуска клиента |
| `cse_skin <weapon> <skin>` | Надевает доступный по уровню скин и сохраняет выбор в профиле |
| `cse_skin_list` | Показывает доступные и заблокированные рецепты |
| `cse_operator <t|ct> <model>` | Валидирует и сохраняет оперативника выбранной стороны |
| `CHudXPBar::Init()` / `CHudXPBar::Draw()` | Регистрируют и рисуют HUD-элемент `XPBar` |

## Следующие этапы

Бот-множитель подключён на клиенте через userinfo-ключ `*bot`, серверный этап для него не нужен.
Следующий этап для скинов — серверная подмена `p`-модели и precache в ReGameDLL; HUD XP уже
реализован, но требует отдельной визуальной проверки в игре.
