# План: исследование «свои действия на картах» (кнопки и триггеры, видимые всем)

Статус: статическое исследование завершено; исходник и производный BSP стендовой карты проверены компиляцией, игровой стенд ещё не запускался.

## Зачем

Вопрос владельца проекта: возможно ли сделать на карте своё действие — нажатие кнопки или вход в
триггер, — чтобы оно произошло на сервере и было корректно видно всем игрокам.

| Вопрос | Решение |
|--------|---------|
| Исходник карты | Редактируемый `.map` в Hammer / J.A.C.K. → компиляция в `.bsp`. Существующий `.bsp` редактировать в редакторе нельзя: нужен его исходник либо декомпиляция с отдельной проверкой результата |
| Какие действия исследуем | Штатные эффекты HL/CS, игровые действия (оружие, HP, очки), существующие HUD-тексты и отдельный кастомный HUD-эвент |
| Объём первой итерации | Исследование и воспроизводимый протокол стенда. Исходник стендовой карты создан; BSP собран локально для проверки, но реализацию и install-скрипт не создаём |
| Готовность результата | Статический документ готов после подтверждения утверждений исходниками. Результаты запуска — отдельное дополнение и не подменяют чтение кода |

Главный тезис, который документ обязан обосновать на исходниках:

- карту с действиями можно сделать без C++ в пределах штатных сущностей;
- для нового серверного поведения нужен серверный код или серверное расширение;
- для нового клиентского HUD-элемента нужен и серверный контракт сообщения, и код `cl_dll`.

Таким образом, это не «три уровня, первые два без C++». Уровни должны быть названы честно:

| Уровень | Что даёт | Новый код |
|---------|----------|-----------|
| 1. Карта и штатные сущности | Кнопки, триггеры, дверь, текст, звук, оружие, HP, очки | Нет |
| 2. Серверное расширение | Свой classname/правила при сохранении существующего клиентского UI | Да, серверный C++ либо поддерживаемый плагин |
| 3. Свой серверный эвент и HUD | Новый сетевой контракт и HUD-виджет клиента | Да, серверный и клиентский C++ |

## Исходная база и способ фиксации фактов

На момент уточнения плана submodules уже инициализированы. Перед написанием документа сохранить его
входные версии командой `git submodule status`; в таблицах документа указывать путь, SHA submodule и
`file:line`. Не ссылаться на старую ветку: план уже находится в `main`.

Серверная логика находится в
`src/cs16-client/3rdparty/ReGameDLL_CS`; CMake подключает её при `BUILD_SERVER`, а игра грузит
`dlls/mp.dll` из `src/cse/cstrike/gameinfo.txt`. Ни один факт об апстриме не брать «по памяти о HLSDK».

## Что подтвердить в исходниках

Порядок чтения: A → B → C → D. После A можно писать раздел про возможности без кода.

### A. Штатные сущности и цепочка активации

| Файл | Что зафиксировать в документе |
|------|-------------------------------|
| `<REGAME>/regamedll/dlls/maprules.cpp`, `maprules.h` | `game_text`, `game_score`, `game_player_equip`, `game_player_hurt`, `game_counter`, `game_counter_set`, `game_team_master`, `game_player_team`. Для `game_text`: `SF_ENVTEXT_ALLPLAYERS = 1`, параметры текста и допустимый стабильный диапазон каналов 1–4. Для `game_player_equip`: `SF_PLAYEREQUIP_USEONLY = 1`. Для `game_player_hurt`: отрицательный `dmg` лечит активатора, положительный наносит урон |
| `<REGAME>/regamedll/dlls/buttons.cpp` | `CBaseButton::ButtonUse`/`ButtonTouch`, spawnflags, `wait`, `delay`, master и передача `pActivator` |
| `<REGAME>/regamedll/dlls/triggers.cpp`, `triggers.h` | `CBaseTrigger::MultiTouch` → `ActivateMultiTrigger`; `trigger_multiple`, `trigger_once`, `trigger_teleport`, `multi_manager`; точное ограничение `MAX_MM_TARGETS = 16`. Отдельно зафиксировать, что `trigger_relay` вызывает цели с собой как активатором и поэтому не годится в цепочке, где цель должна действовать именно на нажавшего игрока |
| `<REGAME>/regamedll/dlls/subs.cpp`, `cbase.h` | `SUB_UseTargets`/`FireTargets`, цепочку `target` → `targetname`, `USE_TYPE`, master и `LINK_ENTITY_TO_CLASS` |
| `<REGAME>/regamedll/dlls/sound.cpp` | `ambient_generic`: числовые флаги `Play Everywhere = 1` и `Start Silent = 16`, а также фактический путь precache |
| `<REGAME>/regamedll/dlls/effects.cpp`, `util.cpp` | `env_sprite`, `env_beam`, `env_shake`, `env_fade`; способ отправки каждого эффекта. Не обобщать все эффекты как один сетевой механизм |
| `<REGAME>/regamedll/dlls/player.cpp` | Серверные операции `AddAccount`, `GiveNamedItem`, здоровье/броня/фраги и доступность денег через карту. В выводе различать «реализуемо сущностью» и «доступно только серверному коду» |

Полный перечень сущностей собирать по `LINK_ENTITY_TO_CLASS` и сверять с FGD, а не ограничивать
список предполагаемыми `game_*`. Базовый FGD — поставляемый вместе с текущим ReGameDLL
`regamedll/extra/Toolkit/GameDefinitionFile/regamedll-cs.fgd`; он привязан к SHA submodule и не заменяет
проверку кода.

Неизвестный classname проверять в `src/xash3d-fwgs/engine/server/sv_game.c`, в частности через путь
`SV_AllocPrivateData`/поиск spawn-функции. Нельзя заранее писать «молча проигнорируется»: текущий
движок логирует `No spawn function for ...` и освобождает edict. Для точечной сущности карта обычно
продолжит работу без эффекта; неизвестная brush-сущность может убрать связанную с ней геометрию/коллизию.
Совместимость отдельно формулировать для текущей сборки Xash/ReGameDLL и для стороннего vanilla-сервера.

### B. Альтернативы и границы расширения

| Где | Что подтвердить и как использовать вывод |
|-----|-------------------------------------------|
| `src/xash3d-fwgs/engine/common/mod_bmodel.c`, `engine/server/sv_cmds.c` | Поддержку внешнего `maps/<map>.ent` и команду/условия entity patch. Это пригодно для прототипирования и git-friendly entity-описания, но не меняет решение хранить исходник своей карты как `.map` |
| `<REGAME>`, CMake и конфигурация запуска | Реальную возможность ReAPI/Metamod-плагина: недостаточно найти hook API; нужно доказать, что установленный загрузчик способен загрузить плагин и обработать новый classname |
| `src/cs16-client/3rdparty/yapb/src/linkage.cpp` | YaPB проксирует `pfnRegUserMsg` в GameDLL. Это уже подтверждённый факт, но он не доказывает поддержку произвольного Metamod/ReAPI-плагина |

Правило архитектуры проекта требует хранить собственные код, карты и ассеты в `src/cse/`. Если для уровня 2
или 3 потребуется патч ReGameDLL, до реализации нужно отдельное решение: поддерживаемый форк с
зафиксированным SHA и явно документированное исключение из правила submodule. Нельзя молча положить
свой C++ в `src/cs16-client/3rdparty/ReGameDLL_CS` или объявить форк предусловием до проверки
плагинного пути.

### C. Новый user message и клиентский HUD

| Файл | Что подтвердить |
|------|-----------------|
| `<REGAME>/regamedll/dlls/client.cpp`, `client.h` | `LinkUserMessages()` и объявления/регистрация `gmsg*`. Имена `gmsg*` не искать в `game.cpp`/`.h`: в текущем коде они в `client.cpp`/`client.h` |
| `<REGAME>/regamedll/CMakeLists.txt` | Новый серверный `.cpp` добавляется в явный список `GAMEDLL_SRCS`, а не подхватывается glob |
| `<REGAME>/regamedll/dlls/*` | Один существующий classname прочитать целиком: `LINK_ENTITY_TO_CLASS` → `KeyValue` → `Spawn` → `Precache` → `Use`. Это образец для `cse_event`, а не шаблон, который копируется заранее |
| `src/cs16-client/cl_dll/**` и `cl_dll/cl_util.h` | Все регистрации `HOOK_MESSAGE`, не только `hud.cpp`: обработчики распределены по `message.cpp`, `text_message.cpp`, HUD-модулям и другим файлам |
| `cl_dll/hud/timer.cpp`, `hud_layout.cpp`, `cl_dll/CMakeLists.txt`, `tools/hud-editor/editor.js` | Сверить существующий HUD-путь и три реестра редактора с [`player-progression-system.md`](player-progression-system.md); в новом документе дать ссылки, без дублирования чужого исследования |

Если собственный message всё-таки нужен, в документе зафиксировать его контракт: имя, версия, payload
не больше текущего лимита, получатели, момент регистрации до подключения клиента, сервер-источник и
клиентский обработчик. Сначала проверить, не покрывается ли задача уже существующими `TextMsg`, `HudText`
или `HudTextPro`.

### D. Сеть, лимиты и доставка карты

| Область | Что зафиксировать |
|---------|-------------------|
| User messages | В текущем Xash `MAX_USERMSG_LENGTH = 2048`, не «около 192 байт». Отдельно оговорить, что это предел именно текущего движка, а не обещание совместимости с GoldSrc/другими клиентами |
| Адресация сообщений | Сверить полный набор `MSG_*`: `MSG_ALL`, `MSG_BROADCAST`, `MSG_ONE`, `MSG_ONE_UNRELIABLE`, `MSG_PVS`, `MSG_PAS`, их `_R` варианты и `MSG_INIT`; выбирать адресацию по семантике, а не называть все рассылки `MSG_ALL` |
| Лимиты сущностей и ресурсов | Сопоставить ограничения движка с `max_edicts 1800` из `gameinfo.txt`; не смешивать лимит числа edicts, leafs и лимиты precache моделей/звуков |
| Карта и ресурсы | Проследить `sv_allowdownload`, `sv_downloadurl`, `cl_allowdownload`, встроенную загрузку ресурсов, отправку CRC и реакцию клиента на другой BSP. Поиск вести не только в `sv_client.c`, а также в `sv_main.c`, `sv_custom.c`, `cl_custom.c` и `cl_parse.c` |

## Проверка

### Статическая проверка — критерий готовности исследования

Перед созданием документа выполнить A–D и проверить:

1. Для каждого включённого в рецепты classname есть `LINK_ENTITY_TO_CLASS` и подтверждённая цепочка `Use`.
2. Для каждого «всем» указан фактический сетевой механизм и получатели.
3. Для каждого лимита/предусловия указан точный исходник, а для FGD — SHA и кодовая сверка.
4. Для будущего кастомного classname описаны обе стороны совместимости: текущая сборка и сторонний сервер.
5. Результат имеет ссылку на стендовый протокол, но отсутствие игровых результатов не маскируется как подтверждённый факт.

### Стенд — отдельная валидация после подготовки инструментов

Стенд-карта `cse_test_actions` — одна комната, старты за обе команды и два независимых клиента. Исходник
карты создан в `src/cse/maps/cse_test_actions.map`; BSP собран J.A.C.K./ZHLT и установлен локально
в `runtime/cstrike/maps/cse_test_actions.bsp` как производный артефакт. Для клиента B нужен отдельный
runtime-каталог или другая машина: один общий runtime
не годится для проверки отсутствующей карты.

| Сущность | Настройка |
|----------|-----------|
| `func_button` `btn_global` | target `mm_global`, «Don't move», wait 3 |
| `multi_manager` `mm_global` | `txt1 0`, `snd1 0`, `door1 0.5`, `score1 1`, `heal1 1` — не более 16 целей; цепочку с `trigger_relay` здесь не использовать |
| `game_text` `txt1` | `CSE TEST OK`, All Players (`1`), channel 3, holdtime 5 |
| `ambient_generic` `snd1` | Поставляемый для теста WAV, Play Everywhere (`1`) и Start Silent (`16`) |
| `func_door` `door1` | Обычная дверь, Toggle |
| `game_score` `score1` | points 1 |
| `game_player_hurt` `heal1` | `dmg = -25`; у активатора перед тестом есть недостающее здоровье |
| `func_button` `btn_equip` | Прямой target `eq1`, чтобы явно проверить передачу активатора |
| `game_player_equip` `eq1` | Use Only (`1`), `weapon_ak47` |
| `trigger_multiple` `trg_global` | target `mm_global`, wait 5 |
| Точечная `cse_unknown_probe` | Без targets; только для отдельной проверки поведения неизвестного classname. Никогда не заменять ей brush-сущность |

Запускать `server.cmd cse_test_actions`. Обычный launcher использует YaPB с квотой 9;
для карты без waypoint-графа есть отдельный режим `server.cmd cse_lobby -nobots`,
который выбирает штатный `mp.dll` без YaPB. В тесте доставки явно задавать и записывать
`sv_allowdownload`, `sv_downloadurl` и `cl_allowdownload`, не полагаться на defaults.

| # | Проверяем | Критерий и что записать |
|---|-----------|--------------------------|
| 1 | `game_text` для всех | Текст на A и B. Негативный контроль: снять All Players и перекомпилировать — текст только на активаторе |
| 2 | Звук | Оба клиента слышат звук из разных точек комнаты; записать фактическое влияние Play Everywhere и расстояния |
| 3 | Репликация | Дверь открыта на обоих клиентах без отдельного собственного user message |
| 4 | Очки и HP | A получает +1 frag и +25 HP только при наличии недостающего здоровья; B видит изменение фрага в табло |
| 5 | Оружие | `btn_equip` выдаёт AK-47 нажавшему, не всем |
| 6 | Триггер и задержка | `trigger_multiple` даёт ту же цепочку; `wait` подавляет повторное срабатывание |
| 7 | Неизвестный classname | В лог попадает ожидаемый `No spawn function ...`; точечная probe не ломает карту. Результат не переносить на неизвестные brush-сущности |
| 8 | Конец раунда | Описать, сбрасывается ли нужное состояние и как задержанный `multi_manager` ведёт себя через рестарт раунда |
| 9 | Доставка: карты нет | У B из отдельного runtime нет BSP: зафиксировать загрузку/отказ при явно записанных download cvars |
| 10 | Доставка: BSP устарел | У B другая версия BSP: зафиксировать CRC-поведение (перезакачка, отключение или иной фактический результат) |
| 11 | Лог и ресурсы | `runtime/engine.log` без ошибок precache; все нужные внешние ресурсы присутствуют и перечислены |

Результаты 1–11 записываются в приложение исследовательского документа после запуска. Они уточняют
практическое поведение, но не меняют критерий готовности статического исследования.

## Не входит в объём

- Форк ReGameDLL_CS, смена URL/SHA submodule или реализация серверного плагина.
- Любой C++: `cse_event`, новый `gmsg`, `MsgFunc_*`, HUD-элемент.
- Версионирование производного BSP, FGD/VHLT, WAD-ассетов и геймплейного дизайна; BSP стенда собран локально только для проверки исходника.
- `tools/install_maps.ps1` и изменение `build-cse.cmd`; здесь описывается только будущий контракт доставки.
- Конфиг-патч сущностей поверх стоковых карт. `.ent` исследуется как альтернатива/прототип, но не выбранный путь поставки.

## Риски

| Риск | Смягчение |
|------|-----------|
| Факты апстрима устареют | SHA submodules и `file:line` в документе |
| FGD не совпадает с включёнными classname | FGD — вспомогательный источник; каждый classname подтверждается кодом |
| Неверно выбран получатель события | Для каждого рецепта фиксировать `pActivator` и конкретный сетевой механизм; не заменять всё `MSG_ALL` |
| Кастомный classname на другом сервере | Отдельно описать поведение point и brush-сущностей, не обещать бесшумную деградацию |
| Изменение ReGameDLL нарушит правило `src/cse/` | До реализации принять и документировать стратегию плагина или форка |
| Карта есть у разработчика, но не у клиента | Отдельные runtime для теста, явные download cvars и проверка устаревшего BSP по CRC |
| У новой карты нет waypoint YaPB | Отключать ботов командой после старта либо использовать отдельный тестовый launcher; не рассчитывать на переменную окружения |
